# Growth classification

Korean version: [growth-classification_ko.md](./growth-classification_ko.md)

`analyzeGrowth` still returns the legacy speed buckets `stall`, `softcap`, `exp`, and `super-exp`. Those names are log10-slope thresholds. They are not a growth shape, and a near-zero bucket is not a resource bottleneck. `idk growth` and the experience snapshot still emit that report so existing KPI output stays put.

`fitGrowth` is the separate artifact. It requires a sampling contract: budget, method `growth-fit-v1`, method version 1, and `windowSec`. `windowSec` is the time window. The sample count does not switch that meaning, including below 1024 points. Shape and speed are different fields. The shapes are candidates on the observed window: `constant`, `polynomial`, `exponential`, `accelerating-log`, `saturating`, or `unknown`. A candidate is not a proof of the asymptotic regime.

Amounts stay in the Engine. `absLog10` is used for positive finite values. A value is narrowed with `toNumber` only when its absolute log10 is inside the safe number range, and only for a value-domain residual. Zero and negative samples are a separate domain. They are not passed through `abs`. A purchase, reset, sign change, or tenfold drop starts a new window. A configured `analytic.softcap` is recorded beside the shape and does not select it.

Breaks are found on every sample before the sampling budget applies, and both sides of each break are kept, so downsampling cannot hide a zero or a drop. Fits use time since the window start, so a large absolute `t` does not change the slope. Value-space fits run in units of the series magnitude, not floored at 1, so a unit change does not change shape. Saturation reads gap-normalized growth rates, so an evenly downsampled trace with uneven gaps is still saturating. An exact tenfold drop is a drop. Coarse cadence keeps a non-positive or nonfinite domain `invalid`. An exact value-space line or parabola is `polynomial` whatever its intercept, unless the log-linear fit is closer still, so a slow exponential stays `exponential`. Irregular spacing is read from the input samples before the budget thins them. From a run, an action opens its window at the first trace state after the action. A trace that retention emptied stays empty. Without a complete action history, windows withhold shape claims. A zero action count counts as complete only when the action counter was observed. A logged action is a reset when the model lists it as a prestige action and a purchase when it is any other non-custom kind, whatever its id. Log values are fitted relative to the first one, so a large log offset does not change the shape, and a moving exact value fit, or an exact log-linear fit with a real slope, is not `constant` even when its log span is tiny. The softcap hint is read at the analyzed run's start. Under a sampling budget, samples are kept per fit window. When the budget cannot give every window enough samples, an evenly spaced subset of windows is fitted and a warning names how many. Acceleration is the quadratic log term standing well above its residual, saturation is judged without the retained gap, and any positive slope has a doubling time. The sampling budget is split at breaks before windows, so each side of a break gets its own share. Value-space fits read amounts outside the Number range as ratios to the window's largest, so a unit change keeps polynomial shapes. Under a tight budget, samples go to windows that can be fitted. The conformance harness checks that exponential, affine, and saturating fixtures keep their window shapes when rescaled and when thinned. A saturating window may end in a flat plateau, but renewed growth after it is not saturation, and its residual is the saturation fit's own, in `log-rate` space. A logged action the model did not list at the traced state is a purchase unless a prestige count change confirms a reset. An exact log-quadratic or power fit keeps precedence over a value fit that is only nearly exact. Thinning keeps a window's samples for the part before it settles on its final value, so a long plateau does not hide saturation. Power laws are also fitted from the start of their break segment, so window partitioning does not change their shape, and a power fit far closer than the log-linear one is not read as exponential. Power laws are fitted on absolute time as well, so a trace that starts late keeps the law's basis. Detected saturation outranks the near-flat, exponential, acceleration, and power readings, so a large baseline under a saturating curve keeps it saturating. When actions of different kinds share a logged id, the row is a purchase unless a prestige count change confirms a reset. Without a complete action history, a window also withholds its residual, speed, and fit diagnostics.

A later Analyzer adapter should pass `GrowthSamplingContract` and read `GrowthFitArtifactV1`. It should not infer a regime from the legacy enum. The structural schema is `idlekit.growth-fit.v1`.

There is no RNG. The formulas and the executed simulation cases are `fixtures/conformance/growth-shapes.json`. The repro label is that file. The slope tolerance is `1e-4`.

Node.js and browser runtimes are not part of the v1 compatibility contract.
