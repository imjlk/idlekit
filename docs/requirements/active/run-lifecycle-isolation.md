# Run lifecycle isolation

## A trial starts from its own model, strategy, and vars {#req-pr03-run-lifecycle-isolation}

Requirement `REQ-PR03-RUN-LIFECYCLE-ISOLATION`. `PR-03` owns it.

`createRunFactory` in `packages/core/src/sim/runFactory.ts` is the production host. `simulateMonteCarlo` binds each draw through it. `compileScenario` copies `initial.vars` with `cloneRunState`. That copy is `deepClonePreservingPrototype`. Numeric prototypes stay. The input scenario object is not the run's vars object. `ctx.E` is shared and is not cloned. Engine operations are treated as immutable: the number engine's `add` returns a new value and does not write the previous one. A custom engine that mutates its values is outside this isolation.

A fresh trial restores a strategy that has both `snapshotState` and `restoreState` to the snapshot taken when the experiment was bound. `continue` does not restore that snapshot, so one session keeps the cursor across active and offline segments. `resume` restores the checkpoint's `snapshotState` bytes. Those bytes are the existing strategy snapshot, not a second serializer. A `StrategyFactory` or `ModelFactory` creates a new instance for `fresh` and `resume`. `continue` keeps the same model instance and, for a factory strategy with the same factory and params, restores that strategy's snapshot onto a new instance. A factory strategy without a snapshot pair keeps its previous instance when the factory and params are the same. Another factory or params starts a new instance without the previous snapshot, and a bound snapshot-backed strategy continued after another strategy starts from its bind snapshot. Snapshot-backed strategies share one object, so those instances are sequential. Factory instances are distinct objects and do not share cursors. Params passed to `bind` for a factory strategy or model are checked against that factory's `paramsSchema` at bind, with the same `Invalid strategy params` error as `compileScenario` (`Invalid model params` for a model). Params for a strategy selected by `ExecutionPlan.strategyId`, or that factory's `defaultParams`, are checked the same way when the run opens. Params marked `validated` (`RunBindOptions.strategy.paramsMode` or `ExecutionPlan.strategyParamsMode`) are already the schema's `result.value`, which the schema need not accept again, so `create` receives them without a second check. Without params, that factory's `defaultParams` are checked in the marked mode. An omitted mode is `legacy-raw`.

A compiled model or strategy with no factory and no snapshot pair is shared and treated as stateless. A strategy with only one of `snapshotState` and `restoreState` has no pair and is shared the same way. Deep-cloning its function closure is not isolation. If the caller sets `statefulModel` or `statefulStrategy` and no factory or snapshot pair can rebuild that closure, `createRunFactory` throws `RunIsolationError` before the loop. The message says a function closure is not cloned into isolation.

`executionStream` and `previewStream` are derived from the base seed, the logical trial id, and the stream name. The same triple is the same seed. The two streams are not equal for a non-empty trial id. Restoring a preview snapshot onto the execution RNG throws. The execution RNG can be snapshotted, cloned through `cloneRunState` inside vars, and restored. `simulateMonteCarlo` still publishes `deriveDrawSeed` on `ctx.seed`. The stream seeds do not replace that draw seed.

`ExecutionPlan` is the minimal resolved-plan object later CLI work can pass in. This host does not parse flags, read files, or discover plugins. `executionPlanIdentity` is canonical JSON of the plan fields only, with object keys sorted at every depth, so equal plans give equal identities. An omitted `strategyParamsMode` has the identity of `legacy-raw`. It is a string key, not a hash. It does not include wall time or a local path. `RunCheckpoint` is in-memory runner metadata. `runner.prestigeReadyAtSec` is the unused slot for a later cooldown. `SimStateJSON` v1 does not gain that field, and a save that omits it still parses. `constraints.minPrestigeIntervalSec` is not enforced here.

`RunInstance.observer` is per trial and does not hold another trial's event buffer. `runScenario` still allocates that buffer for the run. This requirement does not deep-freeze hot state. It does not claim that two step sizes match. It does not register `ExecutionPlan` or `RunCheckpoint` with a contract generator. That registration waits until `TC-05`.

`packages/core/src/sim/runFactory.test.ts` is the executed test host. It is not a production host. The repro label is `0x7103`. The scripted repeat is one non-looping buy over three steps, so each fresh draw ends at one buy. The stateful income fixture calls income twice, at 1 then 2, so the wallet ends at 3 for every draw. The session fixture uses `stepSec` 86400 and one day. `twice-daily` applies `a0,a1,a2,a3` in one binding. A later `offline-heavy` on a new fresh trial applies `a0,a1` again.
