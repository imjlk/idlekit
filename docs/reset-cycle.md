# Reset cycle execution

Korean version: [reset-cycle_ko.md](./reset-cycle_ko.md)

`executeResetCycles` runs a fixed interval, or an explicit list of durations, and commits one reset after each completed cycle. The reset goes through `applyDecisions`, the same payment path as `stepOnce`. It does not grant a tick of income. The adapter builds its action for the current state, so `applyDecisions` is called with `resolveAgainstModel: false` and does not drop a spec or custom action that `model.actions` does not list. `stepOnce` keeps re-reading `model.actions`.

The default adapter uses a prestige action when the model has one. `pointsFrom`, `resetState`, and `multiplierFrom` are not applied again on that path. When no prestige action exists, a complete `Model.prestige` spec is the adapter: `pointsFrom` is the gain, `resetState` writes the next state, and `multiplierFrom` is only compared. The adapter is resolved from the state at each reset boundary, so a prestige action that appears during an interval is used. A model with neither at the boundary needs an explicit adapter. The status is then `unsupported` after the first interval, and no reset is committed. During an interval the strategy does not see the reset action, so the executor is the only reset authority. `horizonSec` counts from the study origin on simulated seconds summed from each runner result and kept in the checkpoint, any runner budget stop censors the cycle, cycle durations are the runner's simulated seconds, a class-based model keeps its methods and receiver, private fields included, through the interval filter, an ordinary custom action that shares the reset's id stays available, a zero horizon admits no interval, an undefined strategy or RNG snapshot is still restored, the boundary action sees the live constraints, and checkpoints copy strategy and RNG snapshots.

Each cycle records absolute `startSec` and `endSec`, cycle-local `durationSec`, `resetAtSec`, `rewardDelta`, and `accumulatedReward`. The delta is the reward gained by that reset. Stock already held is not counted again. A failed condition, cost, or cooldown is `resetSkippedReason` and pays nothing. `cycles` of `0`, `NaN`, or `Infinity`, and an interval of `0`, are rejected. A horizon, `maxCycles`, or step budget stops the run instead of inventing resets.

`analyzePrestigeCycle` remains the legacy interval scan. Its `stability`, `breakEvenSec`, and copied `cycles` values are not evidence of a committed reset. The warnings on that return say so. This artifact does not include those fields. [Reset policy analysis](./reset-cycle-analysis.md) compares intervals on one horizon. Its empirical stability is not a proved steady state.

Node.js and browser runtimes are not part of the v1 compatibility contract.
