# Reset cycle execution

Korean version: [reset-cycle_ko.md](./reset-cycle_ko.md)

`executeResetCycles` runs a fixed interval, or an explicit list of durations, and commits one reset after each completed cycle. The reset goes through `applyDecisions`, the same payment path as `stepOnce`. It does not grant a tick of income. The adapter builds its action for the current state, so `applyDecisions` is called with `resolveAgainstModel: false` and does not drop a spec or custom action that `model.actions` does not list. `stepOnce` keeps re-reading `model.actions`.

The default adapter uses a prestige action when the model has one. `pointsFrom`, `resetState`, and `multiplierFrom` are not applied again on that path. When no prestige action exists, a complete `Model.prestige` spec is the adapter: `pointsFrom` is the gain, `resetState` writes the next state, and `multiplierFrom` is only compared. The adapter is resolved from the state at each reset boundary, so a prestige action that appears during an interval is used. A model with neither at the boundary needs an explicit adapter. The status is then `unsupported` after the first interval, and no reset is committed. During an interval the strategy does not see the reset action, so the executor is the only reset authority. `horizonSec` counts from the study origin on simulated seconds summed from each runner result and kept in the checkpoint, any runner budget stop censors the cycle, cycle durations are the runner's simulated seconds, a class-based model keeps its methods and receiver, private fields included, through the interval filter, an ordinary custom action that shares the reset's id stays available, a zero horizon admits no interval, an undefined strategy or RNG snapshot is still restored, the boundary action sees the live constraints, and checkpoints copy strategy and RNG snapshots.

Each cycle records absolute `startSec` and `endSec`, cycle-local `durationSec`, `resetAtSec`, `rewardDelta`, and `accumulatedReward`. The delta is the reward gained by that reset. Stock already held is not counted again. A failed condition, cost, or cooldown is `resetSkippedReason` and pays nothing. `cycles` of `0`, `NaN`, or `Infinity`, and an interval of `0` or at most the runner's 1e-12 second resolution, are rejected. A horizon, `maxCycles`, or step budget stops the run instead of inventing resets. `maxCycles: 0` censors the run before the first reset. During an interval the strategy sees no prestige action, under a custom adapter too, and the boundary decision reaches `onAction` like an action decided in a step. On a resume the policy lists the cycles to run now: `cycles` more fixed intervals, or the remaining explicit steps. A checkpoint records the id and state version of the strategy that wrote its snapshot, and a resume with another strategy, or a restorable strategy without a snapshot, is rejected. The horizon check allows rounding only, so an interval that ends even 5e-7 seconds past the horizon is censored. Boundary events also reach `ctx.emit`. A checkpoint also records the explicit adapter whose reward it accumulates and its model, and a resume with another one is rejected. A cycle a step budget cut keeps its index, and the resume plays only its remaining seconds under the same planned duration, and its row keeps the start it had before the cut. A checkpoint's elapsed seconds cannot be negative, and an accumulated reward that overflows is rejected. Boundary events reach observers and `ctx.emit` only after the reset passes these checks. The conformance harness checks that a run split between cycles, or inside one by a step budget, resumes to the continuous result. A checkpoint is validated in full before the strategy or RNG is restored: `nextIndex` must be an integer of at least 0, and an RNG snapshot is bound to the generator's `id` and `stateVersion`. A checkpoint rewritten without running a cycle keeps its cut-cycle metadata. An explicit adapter whose reset is unavailable at the boundary records `cannot-apply`. An adapter must return a prestige or custom action that keeps `t`, and its reward must stay finite. With observation off, no observer is notified, resets included. Inside a session segment a reset's `wallT` comes from the runner's elapsed clock. A checkpoint keeps a strategy snapshot only when the strategy has both `snapshotState` and `restoreState`.

`analyzePrestigeCycle` remains the legacy interval scan. Its `stability`, `breakEvenSec`, and copied `cycles` values are not evidence of a committed reset. The warnings on that return say so. This artifact does not include those fields. Comparing reset policies and declaring a steady state belong to a later change.

Node.js and browser runtimes are not part of the v1 compatibility contract.
